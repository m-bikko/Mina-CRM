# Wiki — схема и инструкции для LLM

База знаний проекта Mina CRM (Amina) — CRM и складской учёт для бутика женской одежды. Obsidian-friendly: Graph View, [[wikilinks]], теги, backlinks.

## Структура папок

```
wiki/
├── CLAUDE.md           # этот файл — схема + инструкции
├── index.md            # каталог всех страниц по типам
├── log.md              # хронология операций (ingest/update/fix/lint)
├── raw/                # неизменяемые источники
│   └── assets/         # картинки, скриншоты, диаграммы
└── pages/
    ├── entities/       # модели данных, интеграции, страницы приложения
    ├── concepts/       # архитектура, FIFO, финансовая модель, паттерны
    ├── sources/        # саммари добавленных источников (инциденты, заметки)
    └── analyses/       # ответы на вопросы, сравнения, решения
```

## YAML frontmatter (на каждой странице)

```yaml
---
title: Название страницы
type: entity | concept | source | analysis
tags: [тег1, тег2]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [пути к коду или raw/]
---
```

`updated:` поднимать при каждом редактировании. Даты — ISO (`YYYY-MM-DD`), относительные даты конвертировать в абсолютные.

## Конвенции

- **Wikilinks**: `[[inventory-batch]]`, с алиасом — `[[inventory-batch|партия]]`. Embed картинок — `![[diagram.png]]`.
- **Имена файлов** — kebab-case, на английском. **Контент** — на русском; технические термины не переводить (snapshot, batch, FIFO, session, aggregation).
- Каждая страница должна иметь хотя бы одну входящую ссылку (минимум из `index.md`).
- Умышленно битые `[[wikilinks]]` допустимы — это маркер «страницу стоит создать».
- Не писать: git-историю, точные строки кода (только пути файлов без номеров строк), ephemeral-состояние, секреты, дубли README/CLAUDE.md.

## Операции

- **Query (вопрос о проекте)**: читать `index.md` → нужные страницы → отвечать; ценные анализы сохранять в `pages/analyses/`.
- **Update (изменение кода)**: если затронуты модели, финансовая логика, FIFO, интеграции — обновить страницы, поднять `updated:`, запись в `log.md` (`## [YYYY-MM-DD] fix|feat|refactor|docs | описание`).
- **Ingest (новый файл в `raw/`)**: прочитать → саммари в `pages/sources/` → обновить затронутые страницы → `index.md` → `log.md`.
- **Lint (по запросу)**: противоречия, устаревшие утверждения (verify против кода), страницы-сироты, битые wikilinks, пробелы в покрытии.

## Специфика проекта

- Ключевые темы: [[fifo-inventory|FIFO-учёт]], [[finance-model|финансовая модель]] (баланс/налог/комиссия), [[snapshot-pattern|snapshot-паттерн]], [[delivery-flow|доставка]].
- Критичный инвариант: двойной учёт остатков — `Product.sizes[].quantity` и `InventoryBatch.remainingQuantity` должны меняться синхронно в каждой операции.
- Все денежные операции проходят через MongoDB transactions и пишут [[transaction]] + двигают [[financial-stats]].
